# 企业知识库问答示范：证据记录

这四份一手资料可支持“检索资料、按权限回答、证据不足时停下并交接”的教学示范。它们没有证明本平台已经具备这些能力，也没有证明某家企业因此获得收益。

- 访问与核验日期：2026-10-05。
- 面向读者：正在学习 AI 的复杂大客户销售、客户经理与解决方案人员。
- 状态：研究证据和教学约束。产品能力、生产集成与实际效果仍需分别验证。
- 复用方式：链接原文，概括事实，注明编辑推论。本文没有复制网页全文。

## 1. 主来源

### E1：RAG 原论文

- 出处：[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)，Patrick Lewis 等。
- 时间：2020-05-22 首次提交；2021-04-12 为页面所示 v4 修订日期。论文被 NeurIPS 2020 接收。首次提交、论文修订和访问日期是三种不同时间。
- 支持位置：Abstract；Submission history。
- 正文支持：论文将生成模型与外部文档索引、检索器结合。检索片段参与生成回答。RAG 可用“先找资料，再组织答案”解释。
- 不能证明：上传企业文件后模型就完成了训练；所有 RAG 实现均与原论文相同；任何企业系统的准确率、上线效果或投资回报。
- 证据性质：研究论文及其指定任务实验。本文不复用实验数字作为企业效果承诺。

### E2：Azure AI Search 文档级权限

- 出处：[Document-level access control in Azure AI Search](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview)，Microsoft Learn。
- 时间：页面标注最后更新为 2026-09-17。未据此确认功能首次发布日或任何客户部署日期。
- 支持位置：“Pattern for security trimming using filters”“Enforce document-level permissions at query time”“Approaches for document-level access control”。
- 正文支持：查询可根据用户或组身份排除无权访问的文档。原生权限检查比较身份与索引中的权限元数据。源系统权限变化需要完成相应同步，才反映在检索结果中。
- 不能证明：所有连接器自动继承全部权限；权限撤销立即生效；仅靠提示词即可隔离客户数据；某个应用已经正确配置了身份与授权。
- 能力边界：安全过滤可采用字符串比较。页面中的部分原生 ACL、SharePoint 和 Purview 能力仍标为 preview，不能统称为已全面正式可用。选型时需再核对具体方式、版本和同步限制。
- 证据性质：官方产品机制文档，不是客户部署或收益案例。

### E3：生成回答的限制

- 出处：[FAQ for generative answers](https://learn.microsoft.com/en-us/microsoft-copilot-studio/faqs-generative-answers)，Microsoft Copilot Studio。
- 时间：页面标注最后更新为 2026-05-30。该日期是文档更新，不是能力首次发布或案例发生时间。
- 支持位置：“What are the limitations of generative answers?”“What protections are in place within Copilot Studio for responsible AI?”。
- 正文支持：生成回答可能出错；近似问题也可能得到不同回答。文档明确系统不执行来源准确性检查，来源错误可能呈现在回答中。产品提供限制知识源范围的设置。
- 不能证明：列出引用即完成事实核验；关闭允许脱离知识源回答的设置即可消除错误；多个模型回答一致就说明事实正确。
- 证据性质：官方产品限制说明。本文据此提出“证据不足时追问或交接”的教学规则；这套规则不是官方承诺的通用自动判真能力。

### E4：转接人工的条件

- 出处：[Hand off to a live agent](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-hand-off)，Microsoft Copilot Studio。
- 时间：页面标注最后更新为 2026-08-03。未确认任何企业据此部署的日期。
- 支持位置：正文开头；“Prerequisites”“Explicit triggers”“Context variables available upon handoff”。
- 正文支持：真实人工转接需要连接人工使用的客服平台，可传递会话历史与相关变量。流程可在特定主题主动触发转接。文档还说明，演示网站到达转接节点后可能无法呈现，仍需实现相应集成。
- 不能证明：出现转接按钮或触发转接节点就有人接单；传递上下文等于问题已解决；人工始终在线；上下文可以忽略接收者权限。
- 证据性质：官方功能和集成文档。本文没有实际连接客服系统或验证人工接管。

## 2. 虚构示例场景

示范问题：“客户甲的设备发生故障，可以免费换新吗？我能直接答应客户吗？”

客户甲、客户乙、人员、设备、合同、故障和审批安排均为虚构。资料卡可包括通用售后规程、客户甲合同条款与已废止的旧版规程。身份可包括客户甲的客户经理、其他客户的客户经理和售后工程师。

所有权限、条款和分支结果由示范预设。它们用于解释因果关系，不能冒充真实模型输出、真实检索结果或实际业务验证。身份切换只是教学控件；生产应用的身份应由可信认证与授权流程确定。

## 3. 教学规则与证据约束

| 教学环节 | 示范规则 | 依据与边界 |
|---|---|---|
| 权限检索 | 先确定可用资料，再让模型组织回答。切换身份时，允许进入回答上下文的资料随之改变。 | E2 支持查询权限过滤。生产系统还需验证身份映射、分块权限和权限同步；提示词不能替代授权。 |
| 证据缺失 | 缺少型号、故障条件或适用条款时，明确缺口并追问。可用资料仍不足时，不给确定的权益承诺。 | E3 支持生成错误风险。具体追问与停止条件是本示范设计；“未找到”不等于“资料不存在”。不要向无权用户泄露隐藏资料的内容或存在情况。 |
| 资料版本 | 显示版本与适用日期；只剩旧版、版本冲突或有效性未确认时，标为待核实。 | E3 支持来源错误会影响回答。四份主来源未直接证明自动版本治理，因此版本选择规则属于编辑设计，不能声称模型总能识别旧版。 |
| 业务审批 | 可以解释已有规则；涉及换新承诺或审批时，说明谁有权决定，转入相应流程。 | E4 支持为特定主题设置人工介入。谁能批准、何时审批由虚构业务规则定义，不能说成 RAG 自带审批能力。 |
| 转人工 | 区分“已请求转接”“人工已接手”“问题已解决”。交接内容包括问题、已核实依据、缺口与待决定事项。 | E4 支持平台集成和上下文传递。三个状态需各自有证据；交接摘要仍受接收者权限约束。没有真实集成时，应标注“流程示意”。 |

图解可依次呈现：问题与身份 → 权限过滤 → 检索可用资料 → 检查版本和适用条件 → 有依据地回答、追问或转人工 → 记录处理状态。

“证据足够”应展示为可解释的示范条件，例如是否有适用条款和必要输入。不要把它画成无条件可靠的模型判断，也不要用虚构置信度、准确率或收益数字装饰界面。

## 5. 使用与验收边界

- 本文可以支持内容审稿和教学分支设计，不替代产品实现及生产验收。
- 资料写“支持某功能”，正文就保持能力表述；没有部署证据，不写“已经落地”。

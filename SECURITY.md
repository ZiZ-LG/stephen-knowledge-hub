# Security policy

## Supported version

Security fixes target the latest commit on the default branch.

## Reporting a vulnerability

After the GitHub repository is created, use its **Security → Report a vulnerability** private-reporting form when available. Do not publish exploit details, credentials, tokens, personal information, or private source material in an Issue or Pull Request.

If private vulnerability reporting is not yet enabled, open an Issue containing only a request for the maintainer to establish a private channel. Do not include technical vulnerability details in that Issue.

This repository must never receive production SSH configuration, server credentials, deployment keys, private API tokens, or production environment values. If a credential is accidentally disclosed, revoke it first; repository history rewriting is not a substitute for revocation.
